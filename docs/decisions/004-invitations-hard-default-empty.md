# ADR 004: 邀请名单硬邀请 + 默认不勾不邀请

## 状态

已采纳 · 2026-09-17（增量需求）

## 背景

发布招标时让管理员选择邀请哪些供应商。三种粒度：

1. **硬邀请**：未邀请者看不到招标、不能报价
3. **仅标记**：所有供应商都能报价，仅 UI 提示"已邀请"
2. **软邀请**：未邀请者可看详情、看名次，但报不了价

## 决策

**硬邀请** + **不勾任何供应商 = 不邀请任何人**（收紧默认）。

## 理由

### 选硬邀请

- 需求文档原文："供应商：受邀参与报价"——受邀是访问的前提。
- 商业现实：报价涉及商业机密（甲方底价、对手报价）。未邀请的供应商不应知道该招标存在。
- 复杂度成本低：与已有的"报价隔离"是同一类机制。

### 选"不勾则不邀请"

- 防止误操作：管理员"忘记勾选"远比"勾错"更危险。前者会泄露不该被看到的招标；后者只是漏邀。
- 强制显式确认：必须**主动勾选**至少 1 家供应商，否则招标不会被任何人看到。这给管理员一个"暂停一下，确认选好了"的信号。

### 选可随时调整而非冻结

- 现实场景常需补充邀请遗漏的供应商（比如临时增加一家有资质但初次漏选的）。
- 取消邀请时**保留历史报价**在管理员账面上：审计追溯不断裂。

## 代价

- 管理员必须理解"勾选 = 邀请"的语义。前端 UI 已明确写"默认不邀请任何供应商"。
- 名次接口的"未报价时 rank 为 null"用例中，未邀请的 supplier 连查看权都没有——正确隔离。

## 实现

- 数据库：`tender_invitations` 中间表（UNIQUE 约束 + 双向索引）
- 管理员侧：POST/PATCH `invitedSupplierIds[]` 批量；POST/DELETE `/invitations` 单条
- 供应商侧：4 个接口全部强制 innerJoin 到 `tender_invitations`；PUT 报价返回 403 "您未受邀参与此招标"
