# ADR 003: 名次按"首次提交时间"排序而非"更新时间"

## 状态

已采纳 · 2026-09-17

## 背景

名次规则的平局判定：金额相同时按什么时间排序？两种选择：
1. 首次提交时间（`created_at`）
2. 最近更新时间（`updated_at`）

## 决策

**按首次提交时间排序**。`created_at` 仅在 INSERT 时设置，UPDATE 时永不修改。

## 理由

1. **防止后改者插队**：供应商 A 先报 100 元，B 故意报 99.99 元（同价后改）。若按 `updated_at` 排序，B 后改时间更晚 → 排后面，符合"金额相同先提交者优先"的朴素直觉。若按 `updated_at`，B 后改时间新 → 排前面，与"先提交"语义矛盾。
2. **奖励早报**：激励供应商尽早提交报价（哪怕是保守价），降低管理员在截止前看到"价格反复横跳"的体验负担。
3. **名次稳定**：报价修改不会引起名次波动（除非金额跨越他人），管理员看到的榜单顺序更可预测。

## 代价

供应商若想用更低价格挤进名次，必须**修改金额**——但因为按金额优先，新低价天然赢得名次。这与"鼓励降价"不冲突。

## 实现

`quotes.created_at` 仅在 `INSERT` 时由数据库 `DEFAULT now()` 设置；`upsertQuote` 服务在 UPDATE 时**不触碰** `created_at`，只更新 `amount / note / updated_at`。

测试覆盖：`tests/quote-upsert.test.ts > 重复提交为原地更新（一条记录），created_at 不变` 与 `tests/ranking.test.ts > 修改报价不改名次依据`。
